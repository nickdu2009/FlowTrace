# 安全与合规指南（MVP，必须遵守）

本项目属于抓包与解密类工具，默认按“最小暴露、默认脱敏、明确告知、可审计”的原则设计与实现。

## 1. 数据分类

- **高敏感**：账号密码、token、cookie、session 标识、私钥、证书材料（P12/KEY）、完整请求/响应 body（可能含 PII）
- **中敏感**：Headers、URL（含 query 可能含 token）、导出文件路径与内容
- **低敏感**：统计指标（数量/耗时/大小）、规则命中（不含内容）

## 2. 默认脱敏（必须）

### Headers（不区分大小写）
- 必须脱敏：
  - `Authorization`
  - `Cookie`
  - `Set-Cookie`
- 必须脱敏（包含匹配）：
  - header key 包含：`token`、`secret`、`apikey`、`session`

### 文本内容
- DevLog/日志/错误提示中不得输出真实 token/cookie/账号等
- 需要示例时必须使用伪造数据或打码（例如 `abcd****wxyz`）

## 3. 日志与 DevLog（必须）

- 禁止记录：
  - 真实抓包数据（尤其是 body）
  - 证书私钥与 P12 明文
  - 用户账号、手机号、邮箱等 PII
- 允许记录：
  - 结构化统计（数量、耗时、截断标记）
  - 错误码/异常类型（不包含敏感 payload）

## 4. HTTPS 解密告知（必须）

- 开启 HTTPS 解密前必须：
  - 展示风险提示与用途说明（仅限授权调试）
  - 明确“无法解密所有 App（pinning 例外）”
- 证书页面必须展示：
  - 指纹（SHA-256）
  - 当前状态（已生成/已安装/是否生效，尽可能）

## 5. 证书材料存储（必须）

- 优先使用 Android Keystore（若实现阶段引入，需 ADR 记录）
- 若临时落盘：
  - 必须加密存储
  - 必须支持一键清理
  - 禁止提交到仓库（`.gitignore` 需覆盖）

## 6. 导出（HAR/JSON，必须）

- 默认脱敏开启
- 导出选项允许关闭脱敏时：
  - 必须有醒目提示
  - 必须记录到 DevLog（不包含敏感内容，只记录“关闭脱敏”这一事实）

## 7. 依赖与漏洞（必须）

- 新增依赖必须说明用途与替代方案，并在 ADR 或 DevLog 记录
- 出现已知高危漏洞时优先修复/升级（必要时调整范围并更新 ADR）
